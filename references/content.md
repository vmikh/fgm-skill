# Единый источник контента проекта

Читай при наполнении нескольких экранов, обновлении цифр, размножении компонентов или ревью согласованности данных.

## Один набор, несколько представлений

Сначала найди существующую модель и примеры. Если подходящий канонический источник уже есть, расширь его; не создавай второй набор тех же данных. Если нет, заведи небольшой проектный файл, например `design-content.json`, с кратким описанием, когда структура требует пояснения. Формат выбирай по проекту: JSON/YAML для привязок и проверок, Markdown для небольшого ручного набора.

Храни:
- устойчивые ID сущностей и отношения;
- контекст представления: период, статус, фильтр, роль;
- согласованные значения и примеры состояний;
- источник, дату среза и пометку достоверности: подтверждено, синтетический пример, неизвестно;
- при необходимости — привязки экранов/узлов и область покрытия.

Не сохраняй секреты и лишние персональные данные. В универсальный скилл не переноси внутренний контент проектов.

Если источник — реальный ответ, сохраняй его происхождение. Отсутствующее поле не заменяй нулём; не смешивай неизвестное и неприменимое. Синтетические данные маркируй явно.

## Как обновлять

1. Определи сущность и контекст, затем измени каноническое значение.
2. Найди все связанные представления в пределах задачи. Popular/summary может ссылаться на те же значения, а не иметь независимую копию.
3. Обнови инстансы без перестройки мастеров. Если обнаружил новые правки пользователя после чтения, сначала согласуй актуальное содержимое.
4. Проверь значения, зависимости и форматирование. Укажи, какие связанные представления ещё не синхронизированы; не расширяй задачу молча.

При переносе из файла в макеты не требуется строить отдельный движок или генератор, если небольшой явный набор решает задачу.

## Проверки по смыслу

Выбирай только применимые проверки:
- Название и изображение относятся к одной сущности; пары/участники правдоподобны.
- Даты, Today/Tomorrow и относительные подписи согласованы с датой демонстрационного среза.
- Суммы, счёт по периодам, итог и события сходятся.
- Проценты, единицы, округление, разделители и сокращения единообразны.
- Доступные действия не противоречат состоянию; завершённое, приостановленное и временно заблокированное не смешаны.
- Зависимые значения меняются логично; копия коэффициента или цены не считается корректной только потому, что красиво выглядит.
- Совпадающие значения допустимы по смыслу и после округления. Не делай все числа уникальными ради разнообразия.
- Состояния из матрицы покрыты, редкие примеры не затёрты.

Для спортивных примеров дополнительно учитывай выбранный период расчёта, текущий счёт, линии и уже определившиеся исходы. Это проверка дизайна, а не утверждение правил конкретного поставщика.
